# PRD · 个人资产管理（Asset Manager）

> 本文回答「**要什么**」与「为什么这样定」。实现细节见 [ARCHITECTURE.md](ARCHITECTURE.md)。

| 项 | 值 |
|---|---|
| 版本 | 0.13 |
| 部署形态 | 纯 Web，100% Cloudflare（Workers + Static Assets + D1 + Cron） |
| 用户模型 | **单用户、单密码**，无多租户 |
| 硬约束 | **必须落在 Cloudflare 免费额度内**（不购买 Workers Paid） |
| 默认值 | 显示币种 USD、时区 UTC、界面语言跟随浏览器、行情自动更新开启 |

---

## 1. 目标与非目标

### 1.1 目标
1. 手动记录个人资产：股票、加密货币、现金。
2. 按「券商 / 加密平台 / 现金账户」组织资产，支持平台图标。
3. 随时增删改，**每一次改动都有历史记录可追溯**。
4. 可视化：总资产、分布（类别/账户/币种/标的）、每日走势、持仓明细。
5. 自动获取行情（免费数据源开箱可用），并允许用户接自己的数据源。
6. 初始化与认证对个人自用足够安全，且部署后无需额外配置即可使用。
7. 支持备份导出与导入、中英文切换、时区配置。

### 1.2 非目标（明确不做）
- 多用户、协作、只读分享链接
- 交易流水账本、FIFO、分红、拆股（见 §7 路线图）
- 税务报表、券商对账单自动解析
- 投资建议、选股、回测
- 移动端原生 App（只做响应式 Web）

## 2. 角色与场景

只有一个角色：**本人**（单用户）。典型场景：

| 场景 | 期望 |
|---|---|
| 每周末更新一次价格 | 一屏改完所有持仓价格，一次提交 |
| 新买入一只股票 | 填代码 → 自动带出名称/币种/市场 → 一键取最新价 → 填数量与成本 |
| 想看「钱都在哪」 | 打开总览，看环形图与 treemap，点击下钻 |
| 想知道「最近涨了没」 | 看走势图，切换区间与按类别堆叠 |
| 换手机 / 换账号 | 导出 JSON，新环境导入，历史记录完整 |
| 忘了密码 | 按文档删 `auth` 行后重新初始化，数据不丢 |

## 3. 功能需求

### FR-1 初始化与认证

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1.1 | setup 页是初始化前唯一可访问的页面 | 未初始化时非 setup 请求一律拒绝；初始化后 `/setup` 返回 409 |
| FR-1.2 | 设置密码页提供「生成随机密码」入口 | ≥16 字符强口令，显示明文、可一键复制；也可自行输入（≥12 字符） |
| FR-1.3 | 初始化必须携带部署时生成的一次性 setup token | token 错误 → 401；未初始化时才接受；写入用条件 INSERT 保证并发下只成功一次 |
| FR-1.4 | 密码不以明文或可逆形式入库 | 库里只有不可逆 verifier；无明文、无原始派生 key |
| FR-1.5 | 会话可用 Cookie 维持，且可全部吊销 | `am_session`（HttpOnly、SameSite=Lax、线上 Secure）；默认 30 天；支持「登出所有设备」 |
| FR-1.6 | 修改密码需验证旧密码，并吊销其它会话 | 新密码 ≥12 字符；旧会话立即失效 |
| FR-1.7 | 防暴力破解 | 连续 5 次失败锁定 15 分钟；失败文案不泄露细节 |
| FR-1.8 | 认证必须适配免费版 10ms CPU | PBKDF2 在**浏览器端**执行，Worker 只做一次 SHA-256 |
| FR-1.9 | 主动改密路径 | 设置页可改密码；`must_change` 机制保留备用（如将来改为部署脚本生成初始密码） |

### FR-2 账户管理

| 编号 | 需求 |
|---|---|
| FR-2.1 | 新增/编辑/删除/归档账户；字段：名称、类型（券商/加密平台/现金）、市场、币种、图标、备注 |
| FR-2.2 | 内置平台图标库（52 个精选字母标 + 品牌色）；无匹配时用「名称首字母 + 自动配色」兜底 |
| FR-2.3 | 删除需二次确认；账户下有持仓时要求先清空或显式级联删除 |
| FR-2.4 | 列表展示：图标、名称、类型、市场、币种、备注、折算后市值、占比 |
| FR-2.5 | 归档后的账户与其持仓不出现在总览与统计中，但数据保留、可恢复 |

### FR-3 持仓管理

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-3.1 | 新增/编辑持仓：账户、类别、市场、代码、名称、币种、数量、价格、平均成本、行情覆盖、备注 | 全部手动可填 |
| FR-3.2 | 每次保存数量或价格时追加写入历史（`price_history` / `qty_history`） | 生效日期按用户时区的「今天」 |
| FR-3.3 | 修改数量时默认不自动改平均成本，但提示可同步调整 | 避免静默篡改成本 |
| FR-3.4 | 市值 = 数量 × 价格；盈亏 = (价格 − 平均成本) × 数量；未填成本显示「—」 | 平均成本法 |
| FR-3.5 | 批量更新价格页：一屏列出可改的持仓，一次提交 | 实时显示变化额与百分比，只提交真正改变的记录 |
| FR-3.6 | 价格陈旧提示 | 超过 7 天未更新的持仓在总览顶部列出，并在明细表标黄 |
| FR-3.7 | 支持归档/恢复/删除；删除写入审计日志 | |
| FR-3.8 | 现金账户：数量=余额、价格=1，界面隐藏价格与成本字段 | 统一模型 |

### FR-4 操作历史

| 编号 | 需求 |
|---|---|
| FR-4.1 | 所有写操作自动写审计日志，含 before/after JSON、UTC 时间戳、操作类型、来源 |
| FR-4.2 | 提供历史页：时间倒序、按实体/操作/日期区间筛选、分页 |
| FR-4.3 | 每条可展开查看字段级 diff（旧值 → 新值） |
| FR-4.4 | 审计日志只读，不可编辑或删除（仅随整库替换导入消失——实际上只追加） |
| FR-4.5 | 备份导入时审计日志**只追加不删除**，并记录导入本身 |

### FR-8 备份与导入

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-8.1 | 一键导出 JSON | 含 `schemaVersion` / `appVersion` / `exportedAt` 与全部业务数据 |
| FR-8.2 | 导出**不含**任何凭据 | 不含密码 verifier、会话、第三方 API Key，也不含行情数据源配置（自定义源的请求头可能含 Bearer Token）；导入后需重新初始化、重新填 Key |
| FR-8.8 | 审计日志中的凭据必须脱敏 | 设置类审计只保留「哪些数据源启用」这类无害信息，Key 与请求头写为标记 |
| FR-8.3 | 可选用口令加密 | AES-GCM + PBKDF2 在浏览器完成，口令不出浏览器 |
| FR-8.4 | 导入前必须全量校验与差异预览 | 逐实体显示 新增/覆盖/删除 计数 + 警告；预览不写库 |
| FR-8.5 | 两种模式：合并（按 id 覆盖）/ 覆盖（先清业务数据） | 覆盖模式二次确认，且保留审计日志 |
| FR-8.6 | 导入必须原子或明确告知 | ≤1000 条语句时单事务；超出则分批并提示风险 |
| FR-8.7 | 文档提供 CLI 全量备份与 Time Travel 恢复 | |

### FR-10 行情与走势

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-10.1 | 默认接入免费行情，零配置可用 | 内置 6 个免费数据源 + 1 个自定义源，均无需 Key |
| FR-10.2 | 多源回退 | 一个标的依次尝试，前一个失败顺延（实测限流后自动换源） |
| FR-10.3 | 省 subrequest | 优先批量接口；单次刷新有请求预算上限 |
| FR-10.4 | 代码映射 + 持仓级覆盖 | 按市场推导各源代码；`quote_source` / `quote_symbol` 可逐条改写 |

| FR-10.7 | 每日快照 | Cron 每小时触发、只在配置时区的小时干活；先刷新行情再拍快照；同日不重复；漏跑自愈 |

| FR-10.10 | 失败不阻塞记账 | 抓取失败只提示「数据陈旧」；失败原因可在设置页查看 |

## 5. 关键设计决策（当前生效）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 持仓由用户手动编辑数量/价格/成本，不做交易流水推导 | 录入成本最低；FIFO 等留到后续版本 |
| D2 | 行情**默认开启**（全部免费无 Key 接口） | 失败只影响「新鲜度」，不影响记账正确性 |
| D3 | 单用户单密码，setup token 保护初始化 | 个人自用；避免公网首访抢注 |
| D4 | 前端 React + Vite + TS；**图表与样式全手写** | 依赖少、可审计；实测拒绝 ECharts 后首包从 244KB 降到 91KB |
| D5 | 认证：浏览器端 PBKDF2 + Worker 单次 SHA-256 | 免费版 10ms CPU 限制下的唯一舒适解 |
| D6 | 部署路径：一键按钮（主）+ CLI（备）；不自建部署用 Actions | Workers Builds 已覆盖；CI 只做质量检查 |
| D7 | 快照一天一行、明细存 JSON（按原币种） | 避免「每天×每持仓一行」的读放大；切换显示币种仍能重算历史 |
| D8 | 平均成本法算盈亏 | 需求明确；简单可解释 |
| D9 | 缺汇率时标为「未折算」并从总额排除 | 宁可显示缺失，也不要给出看起来对其实是错的数字 |
| D10 | 图标用「品牌色 + 字母标」而不是官方 logo | 规避商标风险，避免「像但不是」的观感 |
| D11 | 汇率分 manual / auto，手工优先 | 用户可覆盖自动结果且不被下次抓取冲掉 |
| D12 | 汇率按日冻结 | 修掉「改汇率让历史曲线整体平移」的错误语义 |
| D13 | 语言与时区都是设置项，随备份迁移 | 换环境后行为一致 |
| D14 | 服务端按 `Accept-Language` 本地化提示 | 界面切语言后报错也切，不需要额外的语言参数 |

## 6. 页面与信息架构

```
/setup              初始化（唯一公开页）
/login              登录
/                   总览：统计卡 + 走势 + 分布（环形图/treemap）+ 明细表
/accounts           账户列表（含市值/占比、归档开关）
/holdings           持仓列表 + 批量改价
/history            操作历史（筛选 + 字段级 diff）
/settings           显示币种 / 语言 / 时区 / 汇率 / 行情与快照 / 安全 / 数据概览 / 备份导入导出
```

交互约定：筛选写入 URL；深色模式跟随系统；窄屏隐藏次要列。

## 7. 路线图（未做）

1. **CSV 导入**：券商对账单列映射、重复检测、预览后写入
2. **交易日历感知**：非交易日沿用收盘价，避免无意义台阶

6. **TOTP 二次验证**；可选集成 Cloudflare Access
7. **多用户 / 家庭共享**（需重新设计数据隔离）

## 8. 验收方式

每个 FR 都在 `tests/` 中有对应断言（113 个测试，跑在真实 workerd 运行时），关键路径另用真实网络验证过：

| 验证项 | 方式 |
